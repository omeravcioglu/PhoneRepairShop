# Phone Fixer: trailer v1

An 84-second trailer built from the game's own scenes, with an original soundtrack. Everything is generated by scripts in this project, so any shot, caption, note or sound can be changed and the trailer rebuilt.

| Output (in `Marketing/Trailer/`) | |
|---|---|
| `PhoneFixer_Trailer.mp4` | 1920×1080, 60 fps, H.264 High (CRF 16, BT.709 tags) with AAC 320 kb/s / 48 kHz. Mixed to about -14 LUFS with a -1 dB true-peak ceiling (Steam/YouTube level). |
| `PhoneFixer_Trailer_video.mp4` | the picture alone (re-mux a new mix with `--audio-only`) |
| `PhoneFixer_Trailer_audio.wav` | the final mix, 24-bit |
| `stills/` | the first composited frame of every shot (handy for posts) |

## Pipeline

```
Unity (edit mode, headless)                         Python (ArtSource/Trailer)
TrailerRenderer + TrailerShots                      make_textures.py  -> screen/naruto textures (read by Unity)
  per shot: s_####.png    3D frame (2x SSAA)        music.py          -> music/music.wav
            u_####_b/w.png  game UI over black/white sfx.py           -> sfx/*.wav
            manifest.json   sound cues + tracked    edit_trailer.py   -> composite, graphics, mix, encode
                            screen points
```

1. **Textures.** Run `python ArtSource/Trailer/make_textures.py` before the Unity render: some shots load these PNGs.
2. **Frames.**
   - Run it from the menu with **Tools > Phone Fixer > Trailer > Render All Frames**, or with the batch command in `ArtSource/Trailer/README.md` (Unity closed).
   - About 6 GB of PNG, so `-trailerOut` should point outside the project. It takes about 3 minutes on this machine.
   - Two cheaper modes help while framing shots:
     - `-preview 0,0.5,1` writes three stills per shot.
     - `-shots a,b` renders only the named shots.
3. **Music, effects, edit.**
   - Run `python music.py`, then `python sfx.py sfx`, then `python edit_trailer.py --frames <dir>`.
   - The full edit takes about 15 minutes. `--preview 3` gives a rough cut in about 4 minutes.

## How the Unity side works

`Assets/_Project/Scripts/Editor/PhoneFixer/Trailer/`:

| File | Does |
|---|---|
| `TrailerRenderer.cs` | Batch and menu entry points, the frame loop and 2× supersampling. Motion-blur subframes are set per shot. Renders the UI layer, encodes PNGs on worker threads, writes `timeline.json` and the manifests. |
| `TrailerStage.cs` | One opened scene, staged for one shot:<br>- camera and Bokeh depth of field<br>- grade<br>- a per-shot shadow distance (on an in-memory copy of the URP asset)<br>- clip sampling and cross-fades<br>- sound cues and tracked points<br>- game UI control (`UiOnly`, `UiAlpha`, `"Canvas/Element"` lookups)<br>- glow overlays and in-memory props |
| `TrailerKit.cs` | Easing, camera keys (lerp/arc/Catmull-Rom/orbit), `BenchRig` and `ShopRig`:<br>- `BenchRig`: flip, landing spots via the game's `PartsArea`, flights, unscrewing, tool props, the screen image<br>- `ShopRig`: customers, the sliding door, the cat's squash/breathe, walking a path |
| `TrailerShots.cs` | The 28 shots, in edit order. Each shot is a pose function of time, so shots are deterministic and re-render identically. |
| `TrailerScout.cs` | Writes the world bounds of every prop, spot, customer bone and phone part. Used to frame shots from real numbers. |

Nothing is saved: every shot reopens its scene and stages it in memory.

### Gotchas found while building it

- **Skinned meshes don't re-skin in edit-mode batch renders.** Several renders happen inside one editor tick, so only root motion showed and the arms never moved. `Stage` bakes each posed customer into a plain mesh every frame (`SkinnedMeshRenderer.BakeMesh`) and hides the skinned renderer.
  - **This is not a game bug.** In Play mode the Animator skins normally, and the clips are fine: Celebrate raises both arms, Confused scratches the head.
- **`AnimationClip.SampleAnimation` writes only the curves a clip has.** One clip's mouth or eye scale leaks into the next. Each sample now starts from the rest pose.
- **The editor's fake-null `GetComponent` result defeats `??`.** Use `TryGetComponent`.
- **`InteractionHighlighter.DrawOverlay` queues its draws for the whole editor tick.** In a batch run that is every later shot, so the trailer uses real overlay objects (`Stage.AddGlow`).
- **UI names repeat.** The shop HUD has an "Upgrades" key and the modal is also "Upgrades", so use `"ShopScreens/Upgrades"`.
- **The counter is taller than the customers' chins.** Close-ups stand them at the clear end of the counter, slightly further back, on an invisible "apple box" (Mio gets 24 cm), with the camera across the counter top.

## Audio

- **Music.** `music.py` writes every note of the score in code:
  - `HOOK_*`, `VERSE`, `ANSWERS` and `CHORDS` hold the melodies and harmony.
  - `V` holds the Rhodes voicings.
  - `ARC_DB` shapes the mix per bar.
  - Every instrument is synthesised in the same file: music box, FM Rhodes, kalimba, marimba, glockenspiel, additive koto, ocarina lead, phone speaker, finger bass, string pad and the drum kit.
- **Effects.** `edit_trailer.py` places the sound effects at the cues that the Unity shots recorded, so they are frame-exact (screw pops, landings, ticks on the 16ths). `extra_cues()` adds the clock, the counter bells, the card swishes and the title hit.

**Also verified:**
- **Every shot was checked as rendered frames:** contact sheets at the start, middle and end of each shot, and a frame per bar of the composited cut.
- **The music was checked with `analyze_audio.py`:**
  - per-bar chroma against the written chords
  - the loudness arc: intro about -20 LUFS, groove about -15, chorus about -13, break and stinger quiet
  - spectrum balance
  - click scan
  - DC
  - stereo correlation
  - integrated loudness and true peak

**Not verified:**
- **Nobody listened to it.** The music and effects were designed by ear-less reasoning and checked only with measurements. Listen before you publish, especially to:
  - the lead and kalimba timbres
  - the mix balance under the effects
  - the mew

**Staged moments.** The trailer is in-engine, but these moments are staged for the camera and are not gameplay that exists yet:
- the brush cleaning the port (there is no cleaning minigame yet)
- the exploded view and the snap-back rebuild
- the power-on boot screen
- customers celebrating, and paying in mikan
- the cracked-screen, puffy-battery and ramen jobs (the fault meshes exist; the fault system is M3)
- Madame K. walking in (`Walk` has no pathing in the game yet)

Steam asks that trailers show the game. Before publishing, either match these to the game as M3 lands, or keep them clearly in the cozy-montage part of the cut.

**Fonts.** The trailer graphics use Lilita One and Montserrat (both SIL OFL, already installed in the user font folder) and Yu Gothic for 修理. The game UI in the frames still uses LiberationSans; see PF_Unity_Integration.md, "Needs your OK".
