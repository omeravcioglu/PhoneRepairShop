## Rules

- Screen: 640x360 pixels, shown at 3x on 1080p (4x 1440p, 6x 4K). 1 game unit = 1 pixel.
- Files: PNG, RGBA 8-bit, straight (not premultiplied) alpha, no colour profile tricks.
- Names: exactly the file names below. Animated sprites are numbered from 0: name_0.png, name_1.png ...
- Replace a placeholder by saving your PNG over it with the same name, then run Tools > Phone Repair > Run Setup.
- Keep at least 1 px of fully transparent border around every sprite marked 'outline' (the hover outline is drawn there).
- Phone parts are full-canvas layers: every phone layer is the same 104x200 canvas, centred on the phone, with the part painted where it sits. Export each layer of your phone drawing as its own file.
- Pivots are listed per sprite. 'Pixel' pivots are measured in pixels from the bottom-left corner of the image.
- 9-slice sprites list their border as left, bottom, right, top in pixels; the middle stretches.
- Colours: your call. Hues that carry gameplay meaning (hover orange, blocked coral, done green) are drawn by code, not by the art.

## Delivering art

1. Draw the sprite at exactly the size below (pixel art, 1 game pixel = 1 image pixel).
2. Save it as PNG over the placeholder, same file name, under `Assets/_Project/Art/Pixel/`.
3. Run **Tools > Phone Repair > Run Setup**. Your file is never overwritten; the importer applies the pivot, 9-slice and pixel settings, and the prefab and scene pick the new art up.
4. **Tools > Phone Repair > Art Contract Status** lists what is still placeholder.
