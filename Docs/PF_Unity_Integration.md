# Phone Fixer art pass: Unity integration

This brings the "Pocket Diorama" art direction ([PF_Art_Direction.md](PF_Art_Direction.md), plus the design canvas) into the game as a playable vertical slice:

**main menu → shop diorama → counter dialogue / parts drawers / upgrade catalog / pause → repair bench → receipt → back to the shop.**

It sits next to the Milestone 1–2 content and does not modify it. `M1_Workbench`, the Mochi One and the M1/M2 tools, materials and tests are untouched.

## Play it

1. Run **Tools > Phone Fixer > Run Art Setup**. The setup is idempotent: it regenerates the prefabs and the three PF scenes.
2. Open `Assets/_Project/Scenes/PhoneFixer/PF_MainMenu.unity` and press **Play**.

| Where | Input | What happens |
|---|---|---|
| Main menu | **Enter** / *Open the shop* | cream fade to the shop |
| Shop | hover a station | it glows orange and a navy label shows its name and verb (*Workbench · Repair*) |
| | click **Workbench** | goes to the repair bench |
| | click **Counter** | camera moves to a counter close-up; Mrs. Tanabe's dialogue opens. Answer with **1–3**; **Esc** closes it |
| | click **Parts shelf** / press **I** | parts drawers screen |
| | click **Upgrade spot** (orange floor tape) / press **U** | supply catalog |
| | click **Denchi the cat** | squash-and-stretch bounce (petting) |
| | **Esc** | pause menu; game time stops |
| Repair bench | everything from M2 | 1–4 tools, hold to use, right-drag turn, wheel zoom, Space flip, F frame, R reset, Esc deselect |
| | **Enter** / *Power test* | "Fixed!" receipt; **Enter** again hands the phone back and returns to the shop |
| | **B** / *Back to shop* | back to the shop |

## Pipeline

```
Blender generators (ArtSource/Blender/Scripts/build_pf_*.py, build_phone_mochi_dango.py)
   └─ FBX + pf_palette.json + portraits
Unity: Tools > Phone Fixer > Run Art Setup        (PhoneFixerSetup, batch: -executeMethod PhoneRepair.EditorTools.PhoneFixerSetup.RunBatch)
   1 project basics (URP asset, TMP, highlight material: reused)
   2 palette materials  (PhoneFixerMaterials: one URP material per pf_palette.json row, kept once created)
   3 model import       (standard import + remap by material name; customers as Generic rigs, clips renamed)
   4 UI sprites         (PhoneFixerUiKit: generated 9-slice PNGs), portraits imported as sprites
   5 data               (MochiDangoDataSetup, PF tool definitions)
   6 prefabs            (PhoneFixerPrefabs: phone + fault visuals, shop, bench, customers + controller)
   7 rendering          (PhoneFixerRendering: shop URP asset, volumes, sky)
   8 scenes             (PhoneFixerScenes + PhoneFixerHud: PF_MainMenu, PF_Shop, PF_RepairBench)
Unity: Tools > Phone Fixer > Capture Screenshots  (PhoneFixerCapture, batch: -executeMethod PhoneRepair.EditorTools.PhoneFixerCapture.CaptureBatch)
```

## Placeholders (by design, waiting for systems)

**UI content**
- Every number and name in the screens is static content from the designs: wallet, rating, day, queue tickets, stock, prices, upgrade states, diagnosis LCD, objective and receipt lines.
- **Systems that will feed them later:** economy, job queue, fault system (M3), dialogue, upgrades.

**Interactions that don't do anything real yet**
- **Power test** always "passes" and shows the receipt. There is no fault check yet. Ren's lint is a visual fault only, with no cleaning minigame.
- Dialogue answers swap the speech line; *Leave it with me* just closes the dialogue (no job is created).
- The disabled keys (New shop, Settings, Credits, Controls, Photo for the wall) are drawn disabled on purpose.
- *Save & quit to menu* only loads the menu; nothing is saved.

**World and art**
- **Shop tiers:** only Tier 0 is modelled. The orange floor tape (`Shop_UpgradeSlot`) marks where Tier 1 goes.
- **Customer motion:** there is no sitting animation, so waiting customers stand. They don't walk around yet; `Walk` exists but has no pathing.
- **Light script:** only golden hour (16:30) is lit. Morning and evening from the light script are design-only.
- **Japanese text** from the boards (受付, 修理伝票, …) is omitted. The placeholder font has no CJK glyphs.

## Known issues

1. **Over-budget meshes.**
   - **Mochi Dango.** Most of its triangles come from round lens rings, bevels and damage meshes, which nobody sees from the diorama camera (Ren's phone on the shop bench is a full copy). Fix: an LOD1 or a "decor" export with fewer segments, and fewer torus/cylinder segments on internal parts.
   - **Customers.** Most triangles are hair ellipsoids; reduce their segments.
2. **Station glow on big props.** The hover glow is the existing additive overlay (made for phone parts). On the whole workbench seen from 20 m it reads as a warm tint more than an outline. The colour was boosted for the shop; a real outline (inverted hull) would read better.
3. **Customers can't be hovered.** `InteractionHighlighter` only draws `MeshFilter` meshes, so skinned customers cannot glow. The counter is the "talk" station instead.
4. **Depth of field.** The style guide's bench depth of field isn't in. `PhoneRepair.Runtime` has no URP reference, so a focus-follow script needs that assembly reference first. A fixed-focus DoF was tried in the shop and removed: one focus distance can't serve both the diorama and the counter close-up.
5. **Pipeline switching.**
   - `PipelineOverride` switches `QualitySettings.renderPipeline` at runtime and restores it on disable.
   - If the editor crashes in Play mode inside the shop, check *Project Settings > Quality*: the pipeline override there should be empty.
6. **Placeholder font metrics.** Layouts were sized for LiberationSans. When the real fonts go in, re-run the capture and check that the ticket rows, chips and keycap labels still fit. M PLUS Rounded is wider.
